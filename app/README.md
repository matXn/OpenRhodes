# OpenRhodes Android

OpenRhodes 原生 Android 客户端源码。此目录是独立 Gradle 工程，Android application
模块位于 `app/` 子目录（仓库中的 `app/app/`）。ESP 固件在仓库的 `esp_fw/`。

## 功能

- 局域网与蓝牙发现整合在添加灯具流程，优先蓝牙配网，保留 AP 和旧固件兼容入口。
- 按完整 STA MAC 自动合并同一灯具，保留历史地址；列表、小组件显示 MAC 以区分同名灯。
- 常亮/呼吸、滑动调光、轻点开关；具有反光、文字景深和柔和状态光的倾斜卡片。
- 呼吸卡片轻微旋转浮动；20 秒固定时间轴曲线向左滚动，标记在左侧上下运动。
- 呼吸新配置默认 6.8s / 13% / 0.60；实际灯具保存的参数优先。
- 首页下拉刷新使用标题下划线；启动时下划线按亮、暗、亮顺序从左向右扫过后保持。
- 3×2 与 2×2 可缩放桌面组件、实心圆形亮度循环按钮、红绿状态光和 MAC 标签。
- 保存多个 Wi-Fi、忘记网络、隐藏灯具配网热点、复制热点资料（需匹配 ESP 固件）。
- 应用 ID `com.openrhodes.app`；兼容组件类名用于保留既有小组件绑定与旧数据导入。

蓝牙支持配网与加密直连控制：设备可不连接 Wi-Fi，通过 BLE 开关、调光和控制呼吸。添加页先选择“蓝牙直连”或“Wi-Fi”，再点击灯具连接；设备设置集中显示蓝牙状态、Wi-Fi 与配网热点，需要匹配新固件。

## 当前开发版

2.2.19-dev（versionCode 77）。呼吸参数使用 16ms 时间常数的持续滤波，连续拖动不重启渐变计时，理论上 48ms 跟随约 95% 的目标变化；高刷新率的小刻度调整保留浮点累积。主页面回弹和刷新动画可被新的真实下拉打断，并从当前可见位置继续跟手；刷新期间接手不重复发送网络请求。呼吸显示使用持续推进的本地时钟，参数逐帧跟随，周期只改变后续流速。设备回报的相位校准限速为正常流速的 15%，曲线、亮度与灯板运动共用显示进度。呼吸参数滑条使用更细的半透明轨道与向四周渐隐的柔光滑块，静止按住也会在 140ms 内展开，松手或取消后在 220ms 内收回。状态球与灯板共用逐帧亮度，跟随本地调光、开关、设备回报和呼吸参数预览；关灯后光源熄灭，仅保留玻璃表面。呼吸采用持续运动的宽柔黄白色团，模式切换时流速短暂提升到 4 倍并在 1 秒内恢复，位置不会重置。左侧固定的圆形玻璃罩单独显示当前模式：常亮光源从中心向边缘逐渐透明，呼吸光源为缓慢交融的黄白色块。右侧独立胶囊仅显示常亮／呼吸文字，选中底块以 320ms 贝塞尔曲线移动，状态圆不移动。玻璃使用与灯板一致的暖金色、半透明底色与柔和表面反光，不单独绘制边缘高光或描边。Android 12 及以上使用高斯模糊，旧系统保留柔化渐变。桌面图标沿用 2.2.13 的四角补光和原比例配置。呼吸参数滑条按住展开高光，松手或取消后收回。

进入添加页即自动寻找，前台持续续扫；首次未发现或蓝牙暂未就绪会自动重试，返回前台、开启蓝牙或授予权限后自动恢复。后台暂停扫描，连接前等待扫描释放，连接失败后继续寻找并保留错误提示。

添加页与成功动画放在同一个主窗口中，连接等待姓名由窗口顶层的单一 Text 绘制，保存成功时只交接它的布局数据。连接圆环淡出到姓名下移期间复用同一文字节点，避免独立弹窗退出时与主窗口姓名重叠。

首页、详情顶栏和灯板标题显示名称时省略 `-` 及其后缀，完整名称仍保留在设备设置中。首次添加末段显示“滑动调光／轻点开关”，进入详情后保留约 3 秒再淡出，日常进入不再显示。首页只在向下移动超过触摸阈值后接管下拉，刷新及距离回收期间的点击不会重新套用旧下拉位移。

连接方式位于添加页的灯具列表上方，默认蓝牙直连。Wi-Fi 的蓝牙准备、网络选择和密码输入在最终连接动效前完成。进入连接等待位置采用 160ms 淡出、220ms 淡入；等待及状态文案切换期间姓名保持静止。进度按真实协议事件推进，完整 MAC 与控制通道核验、记录保存均成功后才到 100%。连接圆环补满后淡出，姓名从相同坐标连续接入下拉出场。

姓名连续下移带出正方形灯板。灯板展开为长方形后，下方显示“已添加＋设备名”，再播放绿色勾；短暂停留后自动进入详情。首次添加沿用发现名称，手动地址添加默认使用 `Rhodes Light`，之后可在设备设置中改名。灯板使用原有材质与本地高度，成功反馈结束后保持可见，以 380ms 连续上滑至详情位置，起止速度归零；下方说明和勾原地淡出，文字扫描在灯板到位后开始。设备设置统一为灯具名称、连接、设备信息和第三方开源许可，删除操作位于首页灯具的长按菜单。

长设备名统一测量并显示至多两行，十六进制设备后缀完整换到下一行。圆环与文字块垂直居中，灯板下方说明文字水平居中；说明位置按文字上缘计算，并为呼吸浮动预留间距。显示换行不修改保存的名称。

首页按左侧设备标题、下方状态点与 MAC、右侧整数亮度排版。
设备标题使用 Manrope Light 300，MAC 与地址使用 Jost Light 300，亮度使用
Outfit ExtraLight 200；三种字体均附带 OFL 许可，不需要在线下载字体。

`Open Rhodes` 字标由用户提供的 `artwork/openrhodes-source.png` 整体描摹，
保留输入图片中的字距与字形比例。`artwork/openrhodes-wordmark.svg` 与原生 vector
共用轮廓；`python tools/build_wordmark.py` 可重新生成，工具依赖 Pillow、NumPy、
OpenCV 与 Matplotlib。字标来源说明随源码和 APK 保留，界面开源字体的 OFL
授权不适用于这幅独立字标美术素材。

字标与下划线共用动画时钟。待机时下划线高光延后 120ms 向右掠过，宽度 18%、历时 1.8s；
下拉时收成 12%–32% 的蓄力光带，达到阈值厚度增加 25%，松手以约 1.4s 向右释放。
刷新结束后恢复完整横线；短请求也完成一次释放，但不延迟网络结果。保留亮、暗、亮入场，
再次下拉从当前画面接管。页面下拉幅度保留 1.35 倍，光效在线内裁切，无外部阴影。
系统关闭动画时只显示稳定状态。本版本用于开发协作测试，继续使用现有 Debug 签名。

## 构建

需要 **JDK 21**、Android SDK 36、Build Tools 36.0.0，建议使用 Android Studio
安装 SDK。在本目录创建不会提交的 `local.properties`：

```properties
sdk.dir=/absolute/path/to/Android/Sdk
```

Windows 可使用正斜线形式的 SDK 路径。进入本目录后运行：

```sh
./gradlew --no-daemon :app:assembleDebug
./gradlew --no-daemon :app:testDebugUnitTest :app:lintDebug
```

Windows 使用 `gradlew.bat`。APK 输出到 `app/build/outputs/apk/debug/app-debug.apk`。
Gradle wrapper 与依赖版本已经固定，首次构建需要网络下载。

GitHub Releases 中的 APK 是开发测试包，使用项目现有本机 Debug 签名；签名私钥
不进入仓库。队友自行构建的默认 Debug 签名通常不同，不能直接覆盖已安装的发布包。
不要通过卸载来处理签名差异而丢失已保存数据；需先备份或使用单独测试环境。

## 工程结构

- `app/src/main/java/com/openrhodes/domain/`：灯具模型、稳定身份与命令队列。
- `data/`：HTTP、mDNS、BLE 配网、JSON 持久化与旧数据只读导入。
- `ui/`：原生 Compose 界面；`widget/`：RemoteViews 小组件。
- `app/src/test/`：协议、身份、调度、配网状态机及 Robolectric/Skia 视觉测试。
- `web/`：可选浏览器模拟预览，不是 App 运行时界面。
- `tools/emulator_fixture.py`：仅监听本机 loopback 的可选模拟灯具，不连接真实灯具。

视觉测试输出到 `app/build/reports/`，不提交截图、设备转储和构建缓存。
本次开发测试使用 UU/MuMu；模拟器无法替代真机蓝牙射频和各厂商桌面的验证。

## 蓝牙直连

添加页先选“蓝牙直连”或“Wi-Fi”，再点灯具。蓝牙直连在身份与控制通道验证后交接同一安全会话并自动保存；Wi-Fi 先通过蓝牙读取网络选项，提交网络后等待实际局域网可达再保存。已有灯具复用保存的控制通道自动连接，Wi-Fi 管理通过核验 MAC 的局域网通道进行。
仍使用同一调光卡片和按 MAC 合并的设备目录，不需要输入 IP 或 SSID。
手机需开启蓝牙并允许附近设备权限。无能力标识的旧固件会提示升级，配网兼容保留。
协议见 `../esp_fw/docs/bluetooth-control.md`。

## 首次蓝牙连接诊断

搜索阶段只监听广播，不再逐个建立 4.5 秒限时探测连接，避免用户点击时取消探测又立即建连，以及旧直连入口未等待探测释放的竞争。身份仍由正式加密响应核验。添加流程暂停已有蓝牙轮询；选择直控后转交同一安全会话。

这是代码中可确认的连接竞争修复，不等同于已证实所有手机首次失败都由此引起。`RhodesBle` 日志记录建连、MTU、服务发现、读写的阶段和状态码，不记录 Wi-Fi 密码或加密载荷。真实射频成功率仍须实体手机验证；模拟器只能验证界面和流程。

## 已添加灯具的蓝牙重连

完整 MAC 核验成功后，客户端仅缓存对应的蓝牙射频地址，不缓存安全会话或密钥。
冷启动优先直连该地址；缓存尝试最多 5 秒，失效后清除线索并扫描一次。
广播名称和缓存都不作为身份凭据，每条新连接仍须完成 Security 1 并核验响应中的完整 STA MAC。
删除灯具时同时移除此地址缓存，普通断开或切换 Wi-Fi 控制不移除缓存。

普通控制连接以 `0x10` 状态查询结束握手，不再先进入 Wi-Fi 设置、释放租约和重复读状态。
配网流程仍使用原握手；转为蓝牙直控时交接已有安全会话。回到前台会立即查询，
已收到断链回调的 GATT 直接重建；查询时才发现断链也在同次只读查询中恢复一次。
调光写入失败不自动重发，Wi-Fi / VPN 网络变化也不再使已核验的蓝牙会话失效。

`RhodesBle` 日志额外记录各 GATT 阶段、安全握手和首个状态响应的毫秒耗时。
自动测试覆盖缓存重启、旧地址回退、断链恢复、取消、身份不符与写入不重放；
这些检查不能代替实体手机上的射频时延测量。



2.2.12-dev 同时移除详情顶栏额外的 28dp 空白，恢复独立柔化的动态呼吸波纹；呼吸参数滑条按压／拖动时展开高光，松手或取消后收回，滑块测量宽度保持不变以避免数值跳动。



2.2.13-dev 使用最终确认的圆角暖金图标，仅以边缘同色高光补全四角；抵消 Android 自适应背景的默认外扩，保持原图构图比例。
